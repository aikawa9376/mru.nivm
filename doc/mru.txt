*mru.txt*  Lua MRU/MRW tracking for Neovim

Requirements: Neovim 0.10 or later. The optional picker requires fzf-lua and fzf.

SETUP                                                           *mru-setup*
>
  require('mru').setup({ max_entries = 1000 })
<
For lazy.nvim, use event = 'BufReadPre' and opts = {}.
Replace neomru.vim in every instance; do not load both plugins together.

HISTORIES                                                       *mru-histories*

file       Recently visited or saved files.
write      Recently saved files, separate from visits.
directory  Parent directories of recently visited files.

QUERY                                                           *mru-api*
>
  local mru = require('mru')
  mru.list('write', { scope = 'project', period = 'today' })
  mru.list('file', { scope = 'cwd', cwd = '/path/to/project/src' })
  mru.list('file', { scope = 'project', project = '/path/to/project' })
  mru.list('file', { include_missing = true })
  mru.entries('file')
  mru.project_root()
<
Lists are copies, newest first. entries returns records with path, visited_at,
written_at and missing. Unknown timestamps are absent. Queries join known visit
and save times across file/write histories without combining their ordering.

scope defaults to all, or cwd when cwd is supplied without an explicit scope.
project searches upward for the nearest configured root marker, falling back to
cwd. Directory matching respects boundaries. project can set an explicit root.

period accepts all, hour, today, yesterday or week (last seven days). today and
yesterday use local calendar boundaries. since is inclusive and until exclusive
(Unix seconds). MRW filters written_at; MRU uses the latest visit/save unless
time_field = 'visited_at' or 'written_at'. Unknown times do not match bounded
queries. Missing files are hidden by default but retained within history limits.
They become visible again when they return. reload never forgets missing files.

RECORDING AND RENAME                                             *mru-rename*
>
  mru.append('/path/to/file')
  mru.append('/path/to/file', 'write')
  mru.delete('write', { '/path/to/file' })
  mru.rename('/old/file', '/new/file')
  mru.rename('/old/dir', '/new/dir', { directory = true })
  mru.import('file', '/path/to/old-history', { oldfiles = true })
  mru.import('write', '/path/to/write.json')
  mru.import('file', '/path/to/headerless-path-list')
  mru.migrate()
  mru.save()
  mru.reload()
  mru.sync()
<
append without a kind records a file visit and its parent directory. Automatic
BufWritePost records saves in both file and write histories. rename updates only
history; files are not moved. Directory renames include descendants. Collisions
merge the newest known timestamps. Missing paths survive imports and validation.

Defaults exclude all scheme:// URI paths in every history, including existing
entries. Exit validation removes these entries from storage. Automatic recording
and buffer rename tracking always skip URI names, including panels that set
buftype after entering a window. Replacing ignore can allow explicit URI append
or import; URI visits do not record a parent directory.

BufFilePre/Post and successful local OilActionsPost moves update history.
Other integrations can emit User MruRename with data.from, data.to and optional
data.directory. External filesystem moves are not guessed.

PICKER                                                          *mru-picker*
>
  require('mru.fzf').open({ kind = 'write', scope = 'project', period = 'today' })
<
:Mru and :Mrw open the optional fzf-lua picker in the current project.

ctrl-t      Switch MRU/MRW.         ctrl-g      Cycle project/all/cwd.
alt-d       Cycle time periods.     ctrl-h      Toggle missing files.
ctrl-r      Refresh.                ctrl-x      Forget selected history entries.
enter       Open.                   alt-enter   Tab edit.
ctrl-s      Split.                  ctrl-v      Vertical split.
ctrl-q      Send selected paths to quickfix.

Switching and forgetting preserve the query; forgetting never removes files.
Paths come first; muted Seen/Saved times follow with single-space separators.
No column padding is added. Unknown times show --; full paths remain searchable.
Search matches paths only. The header identifies the active MRU/MRW mode.
Paths use LS_COLORS through color-ls, found in stdpath('config')/bin or PATH.
The command inherits Neovim's LS_COLORS and colors actual paths in one batch.
color_cmd accepts a command path or argument list; false selects theme colors.
If unavailable, failed or timed out, the picker falls back to theme colors.
Theme groups: MruFileName (Directory), MruDirectory/MruTime (Comment),
MruMissing (DiagnosticWarn). Times and missing labels always use theme colors.
Picker options also accept query, previewer, color_cmd,
picker (fzf-lua display settings), and actions (functions receiving actual
selected paths, or false).

OPTIONS                                                         *mru-options*

storage_dir       Default: $XDG_CACHE_HOME/neomru or ~/.cache/neomru.
max_entries       Default: 1000; includes retained missing records; 0 retains none.
save_interval     Default: 0; seconds between automatic saves. Buffered changes
                  flush on a later change after the interval, explicit save,
                  import/delete/rename, setup or exit. No background timer.
validate_on_exit  Default: true; prune ignored entries, retaining missing.
follow_links      Default: false; resolve symlinks when true.
focus_oldfiles    Default: false; true seeds both file and write on FocusGained.
project_root      Default: false; fixed root or function(start) returning root/nil.
root_markers      Default: .git, .hg, package.json, pyproject.toml, Cargo.toml,
                  go.mod. Nearest marker wins; .git may be a worktree marker file.
ignore            Optional function(path, kind) returning true to exclude.
histories         file/write/directory subtables with optional path and limit.

COMMANDS                                                        *mru-commands*

:Mru / :Mrw                      Open visited/saved files with fzf-lua.
:MruSave                         Save metadata and regenerate path exports.
:MruReload                       Reread histories; retain missing paths.
:MruMigrate                      Migrate all histories immediately.
:MruImportFile {path}             Import visited history.
:MruImportWrite {path}            Import save history.
:MruImportDirectory {path}        Import directory history.
:MruRename {old} {new}            Rename a file in history only.
:MruRename! {old} {new}           Rename a directory and descendants in history.
:NeoMRUSave / :NeoMRUReload       Aliases.

STORAGE AND MIGRATION                                           *mru-sync*

Each history path has authoritative JSON with schema_version = 1 and a
headerless export for external consumers: one literal path per line, newest
first; empty histories export empty files. Schema versions are independent of
plugin release versions. Storage paths stay under the configured storage_dir.

Existing JSON with version = 1 is accepted and rewritten on save. When JSON is
absent, headerless lists or old 0.3.0 histories and _long companions load. Only
legacy input strips the old header and tab-separated metadata. Native paths
retain literal tabs. First save migrates; MruMigrate converts all immediately.
Known timestamps, rename records and ordering survive; unknown times stay absent.
Imports accept all three formats. Editing exports does not change JSON history.

External consumers must read every export line without skipping the first.
Update and restart running plugin instances together; previous versions expect
the old JSON version field and export header.

Saves lock, reread, replay local changes and atomically replace metadata, then
exports. A crash between replacements may leave an outdated export; the next
save regenerates it. Buffered events before a cross-instance rename follow the
new path. Metadata errors never overwrite storage. A killed process can leave a
lock: confirm no writer is active before removal, then retry MruSave. Failed
saves keep pending changes. The old Vimscript plugin does not use this protocol.

See README.md for configuration examples and development commands.
